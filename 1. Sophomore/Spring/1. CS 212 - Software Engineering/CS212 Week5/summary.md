**Takeaway —** A test is a claim about behaviour that a machine can tell you has stopped being true, and the value is in the *stops*; `roomsvc` had 212 tests that were not evidence, and the question to ask of every test is **if someone broke this behaviour, would this test fail?** The pyramid's proportions are consequences rather than rules — cost scales up, diagnostic precision scales down, and **brittleness scales up, which is the mechanism by which a suite stops being believed** — so defend a budget (60 s in CI, 2 s per file) rather than a shape, because "unit" is undefined, the right shape depends on where your complexity lives, and a containerised Postgres reused across the session makes an integration test cost 5–20 ms. **Assert on the result, not the route**: a test whose assertion is `mock.assert_called_with` passes if the function does nothing else, breaks on a rename, and does not fail when the behaviour breaks. **An integration test that mocks the database has tested your mock**, and since the invariant lives in the database the only test that can demonstrate it is one against real Postgres — two clients, one slot, `[201, 409]`, exactly one row. The transaction-rollback fixture gives ~2 ms and perfect isolation and **cannot be used for anything that commits**, which includes that test. Red-green-refactor runs in seconds to minutes: **watch the red for the right reason**, fake it till you make it, revert after twenty minutes red — and in the kata the transition table is not designed but **emerges at the third test**, when special-casing stops paying. Five studies on TDD, and the careful replication (Fucci 2016) finds **no significant effect of test-*first*, with the benefit tracking small uniform steps and frequent runs** — which is good news, because the discipline is real and TDD enforces it well; this course assesses whether your tests are worth something, not the order you typed them. TDD is genuinely hard for unknown designs, algorithms, concurrency, UI and legacy code, and *"legacy code is code without tests"* is operationally right. Of the five doubles, **prefer fakes** — mocks assert wording and call shape, do not assert that the thing happened, and **`Mock()` passes silently on `assert_called_once_wiht`**. **Adopt BDD's phrasing, skip its tooling**: stakeholders do not write the features, steps are a second codebase matched by regex. **Zero flaky tests, not few** — quarantine on the day, never re-run. **The week's portable habit: break the code and check the test notices. Ten seconds, and it is Week 6 done by hand.**
