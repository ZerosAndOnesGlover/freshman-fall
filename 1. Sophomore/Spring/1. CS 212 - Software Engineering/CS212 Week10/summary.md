**Takeaway —** Across an API boundary, **observable behaviour means other people's code** — unknown, unreachable, uneditable — so renaming a private function is a refactoring and renaming a JSON field is a breaking change. **Hyrum's law**: with enough users, every observable behaviour will be depended on, including key order, error wording, latency and bugs — `roomsvc`'s `GET /bookings` returned insertion order because nothing said otherwise, the timetable generator depended on it, and an index broke the timetable in 2023. **Liskov substitution is the formal compatibility rule** — weaken preconditions, strengthen postconditions — so add optional request fields and response fields, and never add a required field, remove a response field, tighten validation or change a status code; **three traps look safe**, of which the worst is a required field with a default, because round-tripping clients then overwrite user data. **REST is six constraints and statelessness is the one that earns its keep**, since it is what makes horizontal scaling and load balancing work; **HATEOAS is almost never implemented** because clients hard-code paths, and it pays only where available transitions depend on state — which is exactly `slot`, since it saves a client from re-implementing your state machine. **Say "Richardson level 2"** rather than "RESTful". Name state transitions as endpoints rather than exposing an assignable `state` field; **409 is the most important status code in `slot`**, a 5xx for a client's mistake is a defect, and **`POST` is not idempotent**, so an `Idempotency-Key` protects the user's experience where the unique index protects the data. **Error bodies are contract**: `application/problem+json`, branch on a stable `type`, and document which fields are promised. **GraphQL solves one real problem** — `slot`'s week view is 32 requests — and costs five things: HTTP caching gone, **the N+1 moved into your resolvers**, unbounded query cost, **errors returning 200 so every HTTP-level tool sees success**, and per-field authorisation. gRPC buys binary serialisation, HTTP/2 multiplexing, generated clients and first-class streaming, and its transferable lesson is that **the field number is the contract and the name is not** — renaming is free, reusing a number is catastrophic, and JSON chooses the opposite. **Removal, not addition, is the hard part of versioning**, because you cannot remove a field until you know nobody uses it: `roomsvc` has **seventeen deprecated endpoints, the oldest from March 2021**, all still live. Put `/v1/` in the path now, since retrofitting a prefix is itself breaking. **Stripe's transformer chain generalises to a principle: compatibility belongs in a translation layer, not the core** — Adapter across time. **Expand-and-contract has four phases and phase 3 is measurement**: four lines of instrumentation turn *"we think nobody uses it"* into a number, and the caller tag turns an impossible removal into three emails. A deprecation needs a machine-readable marker, **a date**, a usage metric, a named replacement, **and a card on the board**. SemVer works for libraries and badly for services, because a library consumer upgrades when they choose and a service consumer is upgraded when you deploy.
