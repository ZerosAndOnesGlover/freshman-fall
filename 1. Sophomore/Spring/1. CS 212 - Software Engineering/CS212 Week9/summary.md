**Takeaway —** Refactoring changes internal structure **without changing observable behaviour**, and that clause is the definition rather than a guideline — **the operational test is that if a test had to change, it was not a refactoring.** Refactoring is safe because tests tell you when you broke something, so **`confirm_booking`, with eleven tests against ninety-four paths, cannot be refactored safely at all**; *"legacy code is code without tests"* is unkind and exact, since what makes code legacy is that you cannot change it safely. The deadlock — tests need seams, seams need refactoring — is broken by the **characterisation test**, which asserts what the code *does* rather than what it should: write the wrong assertion, read the failure, paste the value in, **and comment that it records rather than endorses**, using coverage over those tests as a checklist for what remains unpinned. **The two hats** — adding functionality or refactoring, never both — make a red test diagnosable in one step and produce independently revertable commits. Refactor opportunistically (rule of three, **preparatory**, comprehension, litter-pickup); **a refactoring fortnight is usually a mistake**, being unreviewable, unrevertable, and an optimisation of code whose future you are guessing at. Four cases are dangerous: no tests, **concurrency** — an extract-method that moves an `INSERT` out of its critical section preserves every unit test and recreates VNC 101 — performance-sensitive code, and a **public interface**, which is Week 10. **A smell is a cheap fallible signal saying *look here***, the same epistemic shape as coverage and linter findings; nine smells account for `roomsvc`, and two get mis-ranked — **Divergent Change is the most serious and is visible only in the `git log`**, detectable by no linter, while **Speculative Generality is easiest to fix and hardest to agree to** (380 lines, 31 commits, zero plugins). **Long Function is a symptom**: the right first move is **Split Phase** — decide (pure), act (one transaction), announce (after the commit) — which makes a notification failure structurally unable to roll back a booking, splits along *what changes for whom*, and lets the line count fall out. **The fix is twelve insertions, one of them DDL**: 23 days to diagnose, four months to ship, **an afternoon of engineering** — and the four months were 487 lines, eleven tests and a departed author. **Eight weeks of this course are what made the afternoon possible**, which is the bill for 60% of lifetime cost falling after release. Large refactorings avoid the false choice between a long branch and one huge commit: **branch by abstraction** in six steps, where step 1 is the only creative one, step 2 is where teams stall (**put a visible denominator on the board**), and step 6 — deciding about the abstraction — is the one everybody forgets; **the strangler fig** replaces a system from outside, capability by capability, with rollback as a routing change, **and the data is the hard part.** **Parallel run** moves W6's oracle into production, where mismatches are a specification. **A rewrite throws away every bug you ever fixed.**
