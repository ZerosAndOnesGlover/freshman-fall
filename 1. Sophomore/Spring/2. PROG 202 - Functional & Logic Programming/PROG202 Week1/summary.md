# PROG 202 · Week 1 · Summary

**Topic —** Types: values as sets, algebraic data types, pattern matching, exhaustiveness, and Hindley–Milner inference. Designing a type so the bug cannot be written, and finding where types stop.
**Lectures —** L03 Types as Sets, Algebraic Data Types, and Why the Compiler Knows the Type You Did Not Write; L04 Pattern Matching, Exhaustiveness, and Making Bad States Unrepresentable.
**Work —** PS 1 (100, fifteen parts, due Friday of Week 2), Quiz 1 (Tuesday, ten minutes, covers Week 0, unmarked). **No lab session this week** — Lab 1 is sat Wednesday of Week 2.
**Takeaway —** A type is a set of values and the arithmetic is literal: `(a,b)` has `|a|×|b|`, `Either a b` has `|a|+|b|`, `a -> b` has `|b|^|a|` — so `Bool -> Maybe Bool` has **nine** values, not six. That arithmetic is a design tool, and the week's measurement proves it: Week 0's `type Session = (String,String,String,Int,Int)` was generated in all **120** field orderings and every one compiled — **12 type-check and 11 of them are wrong**, because 3!×2! permutations are indistinguishable to a synonym. Redesigned with `Day` and `Kind` as sum types and `Course`/`Minutes` as newtypes, **2 are accepted and 1 is wrong**: `start` and `end` swapped, the only pair still sharing a type. A newtype per field gets it to **0** and nobody ships that — it makes `start a < end b` fail to compile (`Couldn't match expected type 'Start' with actual type 'End'`), so you add a conversion and lose the protection. The last hole is a *value* problem and closes in a smart constructor: `mkSession` returns `Either String Session`, so no caller can skip the failure, and a swapped session gets `rejected: PROG 202 LEC Thu: starts at 12:15 and ends at 11:00`. **And that guarantee is only a convention until the export list says `Session` rather than `Session (..)`** — change the one character and `./break` prints `PROG 202 LEC Tue 12:15-11:00` and exits 0, with three `-Wduplicate-exports` warnings for company. Exhaustiveness is only useful on a finite type: for `Kind`, GHC says *Patterns of type 'Kind' not matched: **SEM***; for `String` it emits four clauses about individual characters and **gives up with an ellipsis**. Two crashes `-Wall` does not warn about on GHC 9.4.7 at all: a **partial record selector** (`No match in record selector why` — there is no `-Wincomplete-record-selectors` here) and **`head []`** (`Prelude.head: empty list` — `-Wx-partial` is unrecognised). Inference finds the *principal* type, so it is trustworthy — `f x = if x then 1 else 0` is `Num a => Bool -> a`, not `Bool -> Int` — and a signature is still a **firewall**: with one, `fst`-for-`snd` is reported on the line of the mistake; without one, GHC blames the literal **`150`** four lines away in another function. But not always — a locally self-contradictory mistake (`/` for `div`) is localised perfectly either way, and the rule is that a signature stops a *wrong-but-coherent* type escaping its definition.
**New syntax —** `data`, `|` as "or", `newtype`, `type`, `deriving`, record construction/update/pattern `T {f = v}`, as-patterns `x@p`, `case … of`, guards `| g = e`, `minBound`/`maxBound`, and `Module (T)` against `Module (T (..))`.
