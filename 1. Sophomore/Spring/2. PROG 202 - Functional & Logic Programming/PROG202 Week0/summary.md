**Takeaway —** A program is an expression, not a sequence of commands, and `x = x + 1` is a lie the runtime catches with `<<loop>>`. Purity is what makes an optimisation legal without proof: GCC collapses two calls to a pure C function (0.44 s for one call and for two) and refuses for a function differing by one `calls++` (0.88 s) — and making the counter `static` does not win it back, because the analysis is conservative. GHC never has to prove it. Immutability is affordable because sharing is safe: a persistent `Data.Map` insert costs **560 bytes at 1,000 entries and 1,040 at 1,000,000** — 1.86× for a thousand times the data, which is `log₂` exactly as predicted. The cost is on the other side and it inverts an instinct every student arrives with: `print (sum [1..10⁷], length [1..10⁷])` holds **44 KB**, and naming that list once and using it twice holds **273 MB** — at `-O0` (245 MB) and `-O2` (273 MB) alike, because the gap is *retention*, not the optimiser; what `-O2` adds is *fusion*, which drops the unnamed version's allocation from 1,600 MB to 53 KB and is unavailable to the named one precisely because a name forces sharing. `runghc` is 57× slower than `-O2` and no timing may be quoted from it. `:sprint` is the instrument nobody finds alone: `xs = _` → `[_,_,_,_,_]` after `length` → `[2,4,6,8,10]` after `sum`.
