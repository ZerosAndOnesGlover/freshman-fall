**Takeaway —** A file is a name in a directory, an inode found by number, and blocks found through the inode; xv6 divides its 1,000-block disk into 59 metadata blocks and 941 data blocks, reaches a file's blocks through twelve direct addresses and one indirect block, and therefore cannot hold a file larger than 71,680 bytes — which `bigf` confirmed by writing exactly that and then failing. Directories are files of 16-byte entries scanned linearly, links make names cheap and files independent of them, and reading one byte of a two-deep path costs six disk reads before anything is cached. The page cache removes most of that: a warm random read cost 1.61 µs against 93.9 µs cold, a warm sequential pass ran at 7.9 GB/s against 1.6, and readahead grew its window from 16 to 64 KiB as the pattern became clear. Writes are cached too — 64 MiB "written" in 15 ms, with `Dirty` rising by exactly that and staying at its peak for the fifteen seconds `dirty_expire_centisecs` allows — so durability is a separate, expensive request: a 4 KiB write costs 2.9 µs buffered, 27.9 µs with `O_DIRECT`, and about 3,900 µs with any flush, which makes the safe update — write, `fsync`, `rename`, `fsync` the directory — cost 7–10 ms of which the two flushes are all but half a millisecond. ext4 answers xv6's limits with 4 KiB blocks, block groups, extents that describe a 600 KiB file in one line, hashed directories and sparse files, all readable from an image with `debugfs` and no root.
