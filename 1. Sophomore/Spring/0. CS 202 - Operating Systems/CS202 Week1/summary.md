# CS 202 · Week 1 · Summary

**Topic —** The process: what the kernel keeps about it, its states, the context switch, the address space, and a process's life from `fork` to `wait`.
**Lectures —** L04 The Process, and What the Kernel Keeps About It; L05 States, and the Context Switch; L06 Address Spaces, and a Process from `fork` to `wait`.
**Work —** PS 1 (100, due Friday of Week 2), Quiz 1 (Monday, covers Week 0), Lab 1 (unmarked, sat Tuesday of Week 2).
**Takeaway —** A process that is not running is a record: xv6's `struct proc` is 124 bytes, and Linux's `task_struct`, measured by compiling a never-loaded module against this kernel's headers, is 9,920 — mostly pointers to shared structures, which is how a thread is simply a task that shares (27.6 µs to create against 154.3 µs for a process). At any instant almost everything is asleep — one process running of 343 — and a CPU hog and a sleeper on one CPU recorded exactly opposite switch counts, 0/4,788 and 4,748/0. A context switch saves only callee-saved registers and a return address — 20 bytes in xv6, 56 in Linux — because the user registers are already in the trap frame; measured with a pipe ping-pong that caused exactly two switches per round, it costs about 1.6 µs on one CPU and 2.1 µs across two. The FPU state is 1,088 bytes, and Linux now saves it eagerly at every switch rather than lazily as the curriculum describes; xv6 does not save it at all, and two xv6 processes adding 0.5 twenty million times each should each have reached 20,000,000, and on one CPU got answers summing to exactly 40,000,000 — one register, shared; on two CPUs the error became rarer, not absent. Address space is not memory: 256 MiB mapped moved RSS by nothing until it was written.
