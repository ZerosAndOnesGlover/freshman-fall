# CS 202 · Week 0 · Summary

**Topic —** What an operating system is: referee, illusionist and guard; history as problems and mechanisms; kernel and user mode; privileged instructions; the trap mechanism and the system-call interface.
**Lectures —** L01 What an Operating System Is For; L02 Two Modes, and the Wall Between Them; L03 System Calls: the Trap, What It Costs, and What the Numbers Mean.
**Work —** PS 0 (100, due Friday of Week 1), Lab 0 (unmarked, checked off in session, Friday of Week 0). **No quiz** — Quiz 1 in Week 1 covers this week.
**Takeaway —** The kernel is distinguished by where the CPU lets it run, not by what it is: the same `outb` prints a character from ring 0 and kills a process from ring 3, and the difference is the two low bits of `CS` (`0x33` in a user program). Some rules are fixed in silicon and some are set by the kernel — one `prctl` turned `rdtsc` into a fault — and a protection that is configured is not necessarily working: the kernel is built with UMIP, the i5-8250U does not have it, and `sgdt` handed a user program a kernel address. System calls cross the wall through a door the kernel chose at boot; on this machine the crossing costs about 590 ns against 0.30 ns for a function call, a call that does not exist still costs 572 ns, and the vDSO answers `clock_gettime` in 18.5 ns without crossing at all. Batching is how systems pay for the door less often: one 16 MiB file took 14.2 s read a byte at a time and 2.2 ms in 64 KiB buffers.
