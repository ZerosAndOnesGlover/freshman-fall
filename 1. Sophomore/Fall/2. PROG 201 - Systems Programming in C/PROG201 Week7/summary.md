**Takeaway —** The VFS is one interface over many implementations: six filesystem types answered one `statfs`, and two of them reported **zero blocks** because they have no storage — `/proc/self/stat` has `st_size` 0 and reads 40 bytes, so never size a buffer from `st_size` on a file you did not create. **An inode does not contain a name**: names live in directories, and everything else follows. A hard link is another name for the file and a symlink is a file containing a name — delete the original and the first is a complete file while the second dangles. `unlink` frees blocks only when the link count is zero **and** nobody has it open, which is why deleting a log frees no space and `/proc/pid/fd` says `(deleted)`. ext4 stores a symlink target **inside the inode** when it fits in 60 bytes: measured, 14 bytes and **zero blocks** against 75 bytes and one. For data, ext2 uses **12 direct pointers then indirect, double and triple** — 256 pointers per 1 KiB block, a 16 GiB maximum file, and **21 pointer blocks** for a 5 MB file — while ext4 describes the same file in **two extents and no pointer blocks**. On disk: block groups, 11% overhead on a small image, and **backup superblocks at 8193, 24577, 40961** — zero the primary and `e2fsck -b 8193` brings every file back. **The journal is a file**: inode 8, 4 MiB, **6.2%** of a 64 MiB filesystem, and it promises consistency, not durability. `e2fsck`'s five passes are the filesystem's five invariants and its exit status is an API. And durability costs **154×** — 41,980 records/s buffered against 255 with `fsync` each; in place, **`fdatasync` is 3.3× cheaper than `fsync`** (1.26 ms against 4.11); and the safe-write pattern needs an `fsync` on the **directory** as well as the file, which doubles it from 4.17 ms to 8.05.
