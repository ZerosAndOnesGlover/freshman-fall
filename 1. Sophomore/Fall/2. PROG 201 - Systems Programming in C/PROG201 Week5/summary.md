**Takeaway —** A socket is a descriptor with two addresses, and everything from Weeks 1–4 applies to it: no message boundaries, short writes, EOF at 0, and `SIGPIPE` if you write to a closed peer. The listen queue holds **`backlog+1`** and past it the kernel **drops SYNs silently**, so an overloaded server presents as a slow one; `TIME_WAIT` holds an address for 60 s, which is why every listener needs `SO_REUSEADDR` and why 20,000 requests left **11,261 sockets in `TIME_WAIT`** against 28,232 ephemeral ports. Five server architectures, measured: with a trivial response the **iterative server was second fastest** (46,810 req/s) and the comparison meant nothing; with 2 ms of blocking work it fell to **434 req/s and so did `epoll`**, because a blocking handler blocks every connection in an event loop; with 500 µs of CPU the pool won at **12,761**. Pool size follows the work — 437 req/s at one worker and **18,667 at 128** for blocking work, against 8 workers being right for CPU work. C10K measured: an event-driven server held **20,000 connections with no measurable memory growth**, while thread-per-connection failed at **7,637** with `EAGAIN` — Week 3's cgroup ceiling — and **the clients could not tell**. `poll` is *O(watched)* at 4,827 µs for 16,000 descriptors and `epoll` is *O(ready)* at **0.89 µs**; `select` cannot be used above `FD_SETSIZE` = 1024 and fails by aborting. Nagle and delayed ACK cost **38.963 ms per round trip over loopback** against 0.209 ms with `TCP_NODELAY` — **186×**. And copies still matter: `read`+`write` 2,504 MiB/s, `mmap`+`write` 3,367, **`sendfile` 4,206**.
