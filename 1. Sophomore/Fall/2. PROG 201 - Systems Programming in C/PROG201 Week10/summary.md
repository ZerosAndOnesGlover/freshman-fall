# PROG 201 · Week 10 · Summary

**Topic —** Systems security: stack overflows and their defences, return-oriented programming, format-string and heap bugs, and the sanitizers and fuzzers that find them.
**Lectures —** L31 The Stack, the Overflow, and the Defences; L32 Return-Oriented Programming; L33 Format Strings, Heap Bugs, and the Tools That Find Them.
**Work —** PS 9 due Friday; PS 10 (the ROP exploit) released Wednesday, due Friday of Week 11; Quiz 10 (Tuesday, covers Week 9, unmarked). **Lab 9 is sat on Monday of this week; Lab 10 covers this week and is sat on the Monday of Week 11.** Everything is sandboxed on course-supplied binaries under `setarch -R`; the machine-wide ASLR setting is never touched.
**Takeaway —** A stack buffer and the saved return address are adjacent memory, so an unbounded `gets` overwrites the address a function returns to — offset **72** in the target. Every defence since 1996 protects those eight bytes, and the week measures each one as a pair: the **stack canary** turns the shell-spawning overflow into `*** stack smashing detected ***` (exit 134); **NX** turns shellcode-on-the-stack into a SIGSEGV (exit 139) — which is exactly why ROP exists. A **ROP** chain reuses code already in the program: gadgets ending in `ret`, chained through the stack, with `ret` as the interpreter, so NX is satisfied on every byte. A measured 3-gadget chain — a bare `ret` for 16-byte alignment (without which `system`'s `movaps` faults), `pop rdi ; ret` to set the argument, then the target — **spawns a real shell, uid=1000**. `ROPgadget` is not installed so the course ships a 40-line finder, and a **CET-compiled glibc turned out to have zero clean `pop rdi ; ret` gadgets**, so the teaching target supplies its own. **ASLR without PIE leaves the code fixed**, so the hardcoded chain still works with ASLR on; **PIE** closes that. A **format-string** bug is two primitives: `%p` reads the stack (leaking addresses that defeat ASLR) and `%n` writes through a pointer (an arbitrary write). **Heap bugs are silent** — a use-after-free and a double-free both exited cleanly without a sanitizer — while **AddressSanitizer** catches both and names the free and allocation sites. **AFL is not installed, so the course uses libFuzzer** (in clang), coverage-guided, which found a planted out-of-bounds read at **`parser.c:15` from a 13-byte input in ~10 executions**. **CFI** caught a type-confused indirect call and named the target; a **shadow stack** would stop the ROP chain, but this CPU has no CET, so the `endbr64` markers the compiler emitted are **inert** — the same "present but not working" shape as Week 3's `PRIO_INHERIT` and Week 8's lazy binding. The lesson: watch a defence fail before trusting it, and the cheapest exploit to defend against is the bug that never shipped.
