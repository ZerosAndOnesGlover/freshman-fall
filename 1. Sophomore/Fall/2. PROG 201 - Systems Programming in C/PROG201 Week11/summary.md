**Lectures —** L34 Namespaces and Building a Container; L35 Cgroups and Resource Control; L36 Images, OverlayFS, and the Security Boundary.

**Takeaway —** A container is not a virtual machine — it is an ordinary process given private *views* of global resources (namespaces) and a *budget* (cgroups), running on the one shared host kernel. There are **seven namespaces** (PID, net, mount, UTS, IPC, user, cgroup); `clone` makes new ones, `unshare` moves you into new ones, `setns` joins existing ones (which is how `docker exec` works). **`CLONE_NEWUSER` needs no privilege and carries the other five** in the same `clone` call — where each alone returns EPERM for an ordinary user — and the parent writes `uid_map`/`setgroups=deny`/`gid_map` so the child is **root inside** but maps to the real uid outside: this is rootless containers. The **mini-container** (`minic.c`, ~80 lines) was measured: the child is **PID 1** while its host PID is a large number (one process, two PIDs), and its network namespace shows **only `lo`, DOWN**, against the host's three interfaces. But `sethostname` and `mount` are **refused (EPERM)** even to this uid-0-in-namespace process, because AppArmor hands out the user namespace with its capabilities stripped — so namespace *creation* works (PID, net isolation are kernel-enforced properties of existence) while privileged *operations within* do not. That is the fifth **"a mechanism present is not a mechanism working"** finding (after Week 3 `PRIO_INHERIT`, Week 8 lazy binding, Week 10 ASLR-without-PIE and inert CET): **a namespace created is not a capability granted.** Namespaces isolate but do not limit, so **cgroups** supply the budget: cgroup v2 is one unified tree, `memory`/`pids` are **delegated** to the user, and a **100 MB cap OOM-kills the hog at ~90 MB with exit 137** (128 + SIGKILL, cgroup-local — the host is untouched), while `pids.max` turns a fork bomb's next `fork` into **EAGAIN**. Container **startup was measured at ~1 ms** (fork 139 µs, bare clone 119 µs, clone + 6 namespaces 1001 µs) — three orders of magnitude below a VM boot, because a container **shares the host kernel**: `uname -r` is **identical inside and out**, which is both why it is cheap and why its isolation boundary (one host syscall surface, reachable by every container) is weaker than a VM's hardware boundary. **Images are OverlayFS layers** (a shared read-only lower, a per-container writable upper, copy-up on write, whiteouts on delete) finished by `pivot_root` — measured to EPERM here, so described as the mechanism. The security ingredients: **seccomp-BPF** narrows the syscall surface unprivileged (measured — `write` allowed, `getpid` → EPERM, after `PR_SET_NO_NEW_PRIVS`), and **capabilities** split root into ~40 pieces — which is exactly what the AppArmor userns restriction does to the mini-container.
