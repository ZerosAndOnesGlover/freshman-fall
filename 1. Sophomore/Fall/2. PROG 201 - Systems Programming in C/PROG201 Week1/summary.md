**Topic —** File descriptors and Unix I/O: the three tables, what `read` and `write` actually promise, what a system call costs, redirection with `dup2`, pipes, and non-blocking I/O.
**Lectures —** L04 File Descriptors and the Three Tables; L05 `read`, `write`, and What a System Call Costs; L06 `dup2`, Redirection, and Non-Blocking I/O.

**Takeaway —** A descriptor is an index into a per-process table; the file offset lives not in it but in the open file description behind it, which `dup` and `fork` share and a second `open` does not. Measured: `dup` then two writes gives `11112222`, a second `open` gives `2222` with half the data silently lost, and across a `fork` the offset advances for both — which is what makes `>` work. Two system calls are not one: four processes appending with `lseek(SEEK_END)`+`write` kept **4,396 of 80,000 lines**, and the same code with `O_APPEND` kept all 80,000. A system call costs about **1.25 µs** here, so copying 64 MB one byte at a time takes 167.964 s against 0.222 s at 4 KB — a 1000× span that flattens at exactly one page, which is what `stdio` is buying you. `dup2` explains redirection and the `2>&1` ordering rule; a pipe reports EOF only when the last write-end descriptor in every process closes, and `ps -o wchan` names the function a hung reader is parked in.
