# CS 211 · Week 11 · Summary

**Topic —** The complete mini-compiler: a driver over all nine phases, LLVM IR generation, `alloca`+`mem2reg`, pass pipelines, multi-target code generation, and JIT compilation.
**Lectures —** L23 The Whole Compiler, in One Command; L24 LLVM, and the Compiler You Did Not Write.
**Work —** **PROJECT 1 due Friday 17:00 (12.5%)**, PS 10 due the same day, PS 11 (100, released Wednesday, due Week 12 Friday), Lab 11 (unmarked, Friday), Quiz 11 (unmarked, Tuesday, covers Week 10 — the last quiz).
**Takeaway —** Eleven weeks of phases finally run: `cyanc.py gcd.cy 1071 462 --run` returns 21, machine code our compiler produced, and the LLVM JIT agrees with Week 6's interpreter on **11 of 11** calls — differential testing with no oracle. The compiler gets there by refusing to build SSA: every variable becomes an `alloca` and `mem2reg` promotes all 6 slots and 17 load/stores away, inserting the φ-functions using **Week 4's dominance-frontier algorithm**, called as a library. Measured honestly against LLVM, our Week 4–5 optimiser removes 8/0/53/16% where `-O2` removes 72/82/97/81% — and on `cls` ours found *nothing* — but the baselines differ and what Weeks 4–5 actually bought is the ability to read `-O2` output. The week's headline is that we wrote **no back ends and got eight**: 8 instructions on aarch64, 16 on riscv64 (whose base ISA has no divide, so it calls `__moddi3`), 23 on wasm32 (structured control flow), and **124 on AVR**, an 8-bit chip doing 64-bit modulo. Two measurement failures worth keeping: a driver that reported "12 → 2 instructions, 83% removed" because it took `len()` of a `(code, log)` tuple, and a phase-time table that blamed code generation for 82% of compile time when the real cost was `llvm-config` running as a subprocess.
