# Reading Guide: Week 3

---

## Required Reading

### 1. ACM — Code of Ethics and Professional Conduct (2018 revision)
**~8 pages. Free at acm.org/code-of-ethics.**

Read the full document — all four sections. This is the primary text for this week and will be referenced throughout the rest of the semester. Do not skim it. Each principle is short; the work is in thinking through what each one demands in practice, not in parsing dense prose.

**Guiding questions:**
- Principle 1.2 says to avoid "unnecessary" harm. Who determines what is "unnecessary"? The engineer? The employer? The affected user? A court? What happens when these parties disagree?
- The code says in 2.8 that access to systems without authorization is prohibited except "when compelled by the public good." This carve-out is deliberately vague. What criteria would you use to determine whether a given act of unauthorized access meets the "public good" standard? Who gets to make that determination?
- Section 4 calls on ACM members to treat code violations as "inconsistent with membership." Given that ACM membership is voluntary and most computing professionals are not ACM members, how meaningful is this enforcement mechanism?

### 2. Gotterbarn, D., Miller, K., Rogerson, S. — "Software Engineering Code of Ethics" (*Communications of the ACM*, 1997)
**~6 pages. ACM Digital Library (university access).**

The companion code from the IEEE-CS/ACM Software Engineering Ethics task force — focused specifically on software engineering rather than computing broadly. Older than the 2018 ACM Code but useful for seeing how the field's self-understanding has evolved.

**Guiding question:**
- Where does the Software Engineering Code place emphasis that the 2018 ACM Code does not, and vice versa? What does the difference reveal about the evolution of the profession's self-understanding over two decades?

### 3. Vallor, S. — *Technology and the Virtues*, Chapter 1: "Why We Need a New Approach to Technology Ethics"
**~20 pages. University library.**

Shannon Vallor argues that consequentialist frameworks (does this produce good outcomes?) and deontological frameworks (does this follow the right rules?) are both insufficient for technology ethics, and proposes a virtue ethics approach centered on what kinds of character traits technology design cultivates or erodes. This is a more philosophical text than the ACM Code — read it for the argument, not for rules.

**Guiding question:**
- Vallor's virtue ethics approach would ask: "what kind of engineer does building this system make you?" How is this question different from "does this system produce harm?" and "does building this system violate a rule?" Which question do you find most useful for the three scenarios in the lecture?

## Optional / Enrichment Reading

### 4. Winner, L. — "Do Artifacts Have Politics?" (*Daedalus*, 1980)
**~15 pages. Free PDF widely available.**

Langdon Winner's influential argument that designed artifacts embed political and social choices — that technology is not value-neutral. Provides philosophical grounding for the "technical neutrality is a myth" argument introduced in Week 0. Recommended if you want the theoretical foundation for Week 4's algorithmic bias discussion.

### 5. Johnson, D. — *Computer Ethics*, 4th ed., Chapter 2
**University library.**

A standard academic overview of the major ethical frameworks applied to computing — consequentialism, deontology, virtue ethics, social contract theory. Useful if you want a more systematic survey of frameworks than this week's readings provide.
