# Careers Reference Sheet: CSE Career Landscape

A quick-reference map from career path to the courses in your curriculum most directly relevant to it. Use this to inform later elective choices (especially in Year 3/4) and to give shape to discussion question 5 in this week's seminar.

| Career Path | Core Discipline(s) | Most Diagnostic Courses | What the Day-to-Day Actually Looks Like |
| --- | --- | --- | --- |
| **Software Engineer (general / full-stack)** | SE, some CS | PROG 101/102, CS 102, CS 212 | Reading existing code, writing new features, code review, debugging, occasional design discussions |
| **Systems / Infrastructure Engineer** | CS, CE, SE | CS 201, CS 202, PROG 201, CS 321 | Performance debugging, distributed systems design, on-call rotations, low-level optimization |
| **Data Scientist / ML Engineer** | CS, Statistics, Math | MATH 251, MATH 241, CS 331 | Data cleaning (more than you'd expect), model training, evaluation, deployment pipelines |
| **Security Engineer** | CS, SE, adversarial thinking | CS 201, PROG 201, CS 341 | Vulnerability research, code review for security, incident response, red-team/blue-team exercises |
| **Hardware / Embedded Systems Engineer** | CE, EE | ECE 110, CS 201, PHYS 141 | Circuit design, firmware, hardware-software co-design, debugging with oscilloscopes as often as debuggers |
| **Database / Storage Engineer** | CS, SE | CS 102, CS 202, CS 321 | Query optimization, storage engine internals, reliability and crash-recovery engineering |
| **Compiler / Programming Languages Engineer** | CS (theory-heavy) | CS 211, CS 311, MATH 151 | Building language tooling, optimization passes, type systems — a smaller, more specialized market |
| **Research Scientist (industry or academic)** | CS (deep theory) | CS 301, plus a graduate degree | Reading and writing papers, novel algorithm/model design, long unstructured problem time |
| **Engineering Manager / Staff Engineer** | SE + leadership | CS 212, plus real-world experience | Less individual coding over time, more design review, mentorship, cross-team coordination |
| **Technical Founder / Entrepreneur** | All three, shallow-to-deep | Broad — generalist value | Building MVP products fast, wearing every hat, prioritizing ruthlessly under uncertainty |

## A Caution About This Table

This table is a map, not a cage. Almost no one's career follows a single row for 30 years — most engineers drift across several of these over a career, and many roles blend two or three rows simultaneously (e.g., an ML engineer at an early-stage startup is also doing general software engineering and some amount of infrastructure work). Use this table to *orient*, not to *commit*. Year 1 is far too early to lock in a specialization — the goal of this seminar's career discussion is awareness, not premature narrowing.

## Connecting This to CS 190's Semester Arc

Several of these paths carry distinctive ethical weight that this seminar will return to later in the semester:

- **Security Engineer** → directly relevant to Week 8 (Cybersecurity Ethics: Responsible Disclosure, Hacktivism)
- **ML Engineer / Data Scientist** → directly relevant to Week 4 (Algorithmic Bias) and Week 6 (AI and Society)
- **Engineer at a company handling user data (most roles, in practice)** → directly relevant to Week 5 (Privacy and Surveillance)

Keep this table in mind as the semester progresses — the ethical questions raised later aren't abstract; they map onto specific career paths you may be walking toward.
