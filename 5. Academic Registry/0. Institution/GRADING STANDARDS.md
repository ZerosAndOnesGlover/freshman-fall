## Problem Set Grading Rubric (Standard)

Problem sets are graded on a points system. Each problem has a defined point value.
The rubric below applies to most CSE problem sets unless otherwise specified in the course syllabus.

### Correctness (60% of problem score)
| Score | Criteria |
|-------|----------|
| 100% | Solution is fully correct for all cases including edge cases |
| 85% | Solution is correct for most cases; minor error in one case |
| 70% | Solution approach is correct; implementation error prevents full correctness |
| 50% | Correct approach identified; significant implementation gaps |
| 25% | Partially relevant approach; fundamental misunderstanding present |
| 0% | No meaningful attempt or completely incorrect approach |

### Clarity and Explanation (25% of problem score)
| Score | Criteria |
|-------|----------|
| 100% | Explanation is clear, complete, and demonstrates understanding of *why* the solution works |
| 80% | Explanation is mostly clear; minor gaps in reasoning |
| 60% | Explanation present but superficial; does not demonstrate deep understanding |
| 30% | Minimal explanation; solution presented without justification |
| 0% | No explanation |

### Code Quality (15% of problem score — code submissions only)
| Score | Criteria |
|-------|----------|
| 100% | Clean, readable, well-named, well-structured; handles errors gracefully |
| 80% | Mostly clean; minor style issues; logic is clear |
| 60% | Functional but difficult to read; poor naming or structure |
| 30% | Hard to follow; unclear what the code does without running it |
| 0% | Unreadable or no meaningful code |

## Exam Grading

### Written Exam Standards
- **Full credit**: Correct answer with complete, clear work shown
- **Partial credit**: Rubric defined per problem — typically 50–80% for correct approach with minor errors
- **No credit**: Incorrect approach or no meaningful attempt
- **Always show work**: A correct answer with no work shown receives at most 50% unless the problem explicitly does not require work

### Exam Writing Tips (from graders)
1. **State your approach** before diving into calculations. "I will use dynamic programming because this problem has optimal substructure." One sentence. It lets the grader follow your reasoning even if you make an arithmetic error.
2. **Partial credit exists** for correct approaches. Do not leave a problem blank because you can't complete it. Write what you know.
3. **Circle your final answer** for quantitative problems.
4. **Neat handwriting matters** — we cannot award credit for what we cannot read.

## Project Grading Rubric

Projects are graded on:

| Component | Weight | Description |
|-----------|--------|-------------|
| **Correctness** | 35% | Does the system do what it is supposed to do? Does it handle edge cases? |
| **Design Quality** | 25% | Are the architecture and interfaces well-designed? Are tradeoffs justified? |
| **Code Quality** | 20% | Is the code readable, modular, and maintainable? Is it tested? |
| **Documentation** | 10% | Is there a clear README? Are design decisions documented? |
| **Demo Performance** | 10% | Can you demonstrate the system working and explain your implementation under questioning? |

### Demo Evaluation
During project demos, staff ask:
- "Walk me through your design — why did you make this choice?"
- "What would break if we scaled this by 10×?"
- "What was the hardest bug you hit and how did you find it?"
- "What would you do differently if starting over?"

These questions have no single right answer. They evaluate whether you understand your own system.

## GPA and Academic Progress

| Cumulative GPA | Standing | Action |
|----------------|----------|--------|
| ≥ 3.7 | Dean's List eligible | Recognition at semester end |
| ≥ 3.5 | Honors track | Apply for Honors designation at graduation |
| ≥ 2.0 | Good standing | No action required |
| 1.5 – 1.99 | Academic warning | Meet with academic advisor within 2 weeks |
| < 1.5 | Academic probation | Mandatory advisor meeting + academic plan |
| < 1.5 after probation | Academic suspension | Review by Academic Standards Committee |

### Grade Appeals Process
1. Discuss with instructor within 14 days of grade release
2. If unresolved, submit formal appeal to Department Academic Affairs Coordinator
3. If still unresolved, escalate to College Academic Appeals Committee
4. Final appeals to Provost's Academic Standards Office (rare; for procedural violations only)
